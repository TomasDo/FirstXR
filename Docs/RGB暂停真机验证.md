# RGB 暂停真机验证（2026-09-29）

本轮在 Beam Pro X4100 + XREAL One Pro 上验证。连续 5 分钟使用的 APK SHA-256 为 `e75b5db8370a3d967c86bf9a93c44630a5ef7f086400ca2b53c6c505340a9a85`（18:08:08 安装）。后续发现 XR-only 无左眼帧时的编码器崩溃，加入启动保护后，当前 `Builds/First XR.apk` 的 SHA-256 为 `4670cdf7740a2c05657eaa91cabbddb5309c128d96cb67b902e956e56bd6a5d8`（18:26:11 覆盖安装）。最终 Unity EditMode 测试 121/121 通过，模拟导航端测试 51/51 通过。

RGB 功能由 `RgbFeaturePolicy.Enabled` 统一关闭。相机服务在权限、相机对象、采集及重试之前返回；预览、手势切片、MediaPipe/GPU 回读和 RGB RTP 均被拦截。本地按钮显示“RGB 已暂停”并禁用。真机发送 RGB 开启命令时返回 `ACK accepted=false`、`ObservationStatus.error=RGB 已暂停`；测试后模拟端的媒体接收已关闭。纯 XR 镜像代码路径保留，尚未取得有效左眼画面的实机证据。

与同一模拟导航端连接并加载模型、CT 资源后，连续采集 310 秒（10 个完整 30 秒窗口）。应用和眼镜外接显示保持连接。日志中 RGB 原生读取、MediaPipe、GPU 回读及致命异常计数均为 0。16,346 个界面帧样本中，各窗口 p95 为 20.8–26.8 ms，最长 94.4 ms，超过 100 ms 的帧为 0。Beam Pro 监看/连接页切换正常；模拟端将 CT 切片偏移从 39.6 mm 调为 40.6 mm 后，Beam Pro 正确显示 40.6 mm，已恢复 39.6 mm。

导航延迟告警仍出现：10 个窗口共进入“导航数据延迟”18 次、“导航数据中断”15 次，导航帧龄最高 3615.6 ms。gRPC 接收间隔最高 3704.6 ms，接收时源帧年龄最高 3568 ms；收到帧到 Unity 应用的窗口 p95 为 17.4–21.7 ms。手机相对主机时间约落后 92 ms（最佳 ADB 往返 58.8 ms），无法解释秒级积压。模拟端同期 170 次、每秒一次的本机采样显示生成帧年龄最高 40.4 ms、序号每秒增长 26–29；数据指向模拟端生成之后、Unity 收到之前的传输/接收积压，尚未区分 gRPC 内部队列、网络或手机端 HTTP/2 读取。

模拟导航端控制台原先会在处理新 RGB/组合视频请求前先停止旧串流，致使客户端即使拒绝 RGB，已有 XR 镜像仍被前一条停止命令关闭。已在实际模拟端源码中增加基于客户端能力声明的前置拒绝，并完成 51 项测试，其中新增测试覆盖已有 XR-only 串流下 RGB-only 和组合请求均不改变原状态。**当前运行中的 Node 服务尚未重启，仍执行旧代码；重启后才会采用此修复。**

5 分钟观察结束后，单独请求 XR-only 镜像曾得到成功 ACK，随即 Beam Pro 进程在 XREAL SDK 编码器的渲染线程中因未捕获异常触发 SIGABRT；当时左眼帧不可用，服务器也没有收到有效 RTP。最终 APK 已增加无有效左眼帧时拒绝启动编码器的保护；真机重测返回失败 ACK 与明确原因，应用继续运行。此项保护不等于已验证有效 XR 左眼帧的编码链路，后者仍是开放问题。

本轮外接显示为安全显示，ADB 未能捕获眼镜画面；眼镜内文字和 XR 镜像内容仍需人工目视确认。没有相同采样方法的 RGB 启用基线，因此不能把本轮帧耗时直接解释为可量化的前后改善。没有修改导航延迟 200/500 ms 阈值。

原始证据位于 `Logs/rgb-pause/`：`editmode-xr-guard-results.xml`、`android-build-xr-guard.log`、`device-final-5min.json`、`server-final-samples.json`、`beam-pro-connection-page.png`、`beam-pro-ct-offset-40.6.png`。
